1. 整体架构概览

GBrain 是一个 Postgres 原生的个人知识图谱引擎，为 AI 代理提供混合 RAG 检索、实体图谱遍历和知识进化能力。核心设计哲学：Contract-First（契约优先）——CLI 和 MCP 服务器从同一份操作定义自动生成。

关键设计决策

动态导入（按需加载）

export async function createEngine(config) {
  switch (config.engine) {
    case 'pglite':
      const { PGLiteEngine } = await import('./pglite-engine.ts');
      return new PGLiteEngine();
    case 'postgres':
      const { PostgresEngine } = await import('./postgres-engine.ts');
      return new PostgresEngine();
  }
}

src/core/engine-factory.ts — PGLite WASM 不会为 Postgres 用户加载

引擎对等保障

  • test/e2e/engine-parity.test.ts — 相同数据集上对比两引擎结果
  • test/schema-bootstrap-coverage.test.ts — 前向引用列必须有 bootstrap 覆盖
  • test/e2e/schema-drift.test.ts — Schema 差异检测

多源隔离机制

所有数据表的核心唯一约束为 (source_id, slug)，而非单独的 slug。

-- 页面表的唯一性约束
UNIQUE (source_id, slug) WHERE deleted_at IS NULL

-- 读取操作强制源过滤
sourceScopeOpts(ctx) → 优先级:
  ctx.auth.allowedSources (联邦数组) > ctx.sourceId (标量) > 无

两个组织轴：

  • Brain（大脑） = 哪个数据库。路由: --brain, GBRAIN_BRAIN_ID。默认: host
  • Source（源） = 数据库内的哪个内容仓库。路由: --source, GBRAIN_SOURCE。默认: default

Operation 接口结构

interface Operation {
  name: string;              // 操作唯一名 (e.g. 'search', 'put_page')
  description: string;       // MCP 工具描述
  params: Record<string, ParamDef>;  // 参数 schema
  handler: (ctx: OperationContext, params) => Promise<unknown>;
  mutating?: boolean;        // 是否写操作
  scope: 'read' | 'write' | 'admin' | 'sources_admin';  // 权限范围
  localOnly?: boolean;       // 仅本地 (protected-name 任务)
  cliHints?: { name: string; hidden?: boolean };  // CLI 命令映射
}

OperationContext 信任边界

interface OperationContext {
  engine: BrainEngine;
  config: GBrainConfig;
  logger: Logger;
  remote: boolean;        // 核心安全字段：false=可信CLI, true=不可信远程
  sourceId?: string;      // 源隔离
  auth?: AuthInfo;        // OAuth 认证信息
  takesHoldersAllowList?: string[];  // Takes 持有者白名单
}
入口remote说明
src/cli.tsfalse可信本地 CLI 调用者
src/mcp/server.ts (stdio)true不可信 MCP stdio 调用者
src/commands/serve-http.tstrue不可信 HTTP/OAuth 调用者
gbrain call <op>false受信本地快捷路径

Fail-closed 原则：ctx.remote === undefined 被视为远程/不可信

Worker 执行流程

launchJob(job, lockToken):
  1. 创建 AbortController (per-job)
  2. 启动锁续约 setInterval (lockDuration/2 间隔)
     → runLockRenewalTick() 纯函数, 结果分类:
       ok | cancelled | lock_lost | should_abort
  3. 注册 grace-eviction timer (abort 后 30s 强制驱逐)
  4. 注册 per-job wall-clock timeout (如果 timeout_ms 设置)
  5. executeJob() → handler(context)
     .finally(): cancelled=true, 清理 timers, 检查 RSS
     .catch(): 捕获 executeJob 链内未处理异常

基础设施中止处理 (INFRASTRUCTURE_ABORT_REASONS):
  lock-renewal-failed / lock-lost → 不调用 failJob
  → 让停滞检测器重新排队 (不消耗 attempts)

导入管道详解

src/core/import-file.ts 是核心导入入口（~1700行），处理流程：

  1. Markdown 解析：frontmatter + 正文分离，代码围栏提取
  2. 分块：
    • recursive.ts — 递归分块（默认）
    • code.ts — 代码感知分块（tree-sitter）
    • 围栏代码块独立分块（chunk_source='fenced_code'）
  3. 内容健全性检查：assessContentSanity() — 隔离/拒绝垃圾内容
  4. 嵌入：embedBatch() → AI Gateway → 向量存储
  5. 上下文检索前缀：为每个分块生成 LLM 摘要前缀（contextual retrieval）
  6. 链接提取：实体引用、时间线条目、自动链接
  7. 原子写入：writePageThrough() — 页面 + 分块 + 链接在同一事务中

知识图谱

-- 图谱遍历 (traverseGraph)
WITH RECURSIVE bfs AS (
  SELECT from_slug, to_slug, link_type, 1 AS depth
  FROM links WHERE from_slug = $1
  UNION ALL
  SELECT l.from_slug, l.to_slug, l.link_type, bfs.depth + 1
  FROM links l JOIN bfs ON l.from_slug = bfs.to_slug
  WHERE bfs.depth < $2
)
SELECT * FROM bfs

部署步骤

开发环境

# 1. 安装 Bun (>=1.3.10)
curl -fsSL https://bun.sh/install | bash

# 2. 克隆并安装依赖
git clone https://github.com/garrytan/gbrain.git
cd gbrain
bun install

# 3. 初始化 (PGLite 零配置)
bun run src/cli.ts init

# 4. 运行测试
bun run test          # 单元测试
bun run verify        # 静态检查 + 类型检查
bun run ci:local      # 完整 CI 门禁 (需 Docker)

# 5. 开发模式运行
bun run src/cli.ts <command>

生产部署

# 1. 编译二进制
bun build --compile --outfile bin/gbrain src/cli.ts

# 2. 或使用 Supabase (大规模)
gbrain init  # 选择 Postgres + pgvector

# 3. 启动 MCP 服务
gbrain serve             # stdio 模式
gbrain serve --http      # HTTP + OAuth

# 4. 后台任务
gbrain autopilot --install --repo ~/brain

# 5. 健康检查
gbrain doctor --fix

# PGLite → Postgres 迁移
gbrain migrate --to supabase

Minions Worker 生命周期

Worker 启动:
  gbrain jobs work --queue default --concurrency 4

运行循环:
  while (running):
    promoteDelayed()          # 延迟作业提升
    claim(lockToken, ...)     # 声明作业 (带连接错误重连)
    → 静默时间检查 (quiet-hours)
    → launchJob()             # 启动异步执行
      锁续约 (setInterval, lockDuration/2)
      超时检测 (per-job timeout_ms)
      RSS 看门狗 (periodic + post-job)
      健康检查 (DB 探针 + 停滞检测)

优雅关闭:
  SIGTERM → running=false → shutdownAbort.abort()
  → 等待 in-flight 作业 (30s 超时)
  → 清理 timers, listeners
