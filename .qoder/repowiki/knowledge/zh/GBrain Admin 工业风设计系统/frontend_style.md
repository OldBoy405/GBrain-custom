## 1. 核心系统与美学方向
GBrain 的管理控制台（`admin/`）采用**工业/实用主义（Industrial/Utilitarian）**风格，定位为开发者基础设施的运维驾驶舱。其设计哲学遵循 Steve Krug 的《Don't Make Me Think》，强调功能优先、数据密集且零装饰。

- **视觉基调**：深色主题（Dark Theme Only），模拟 Supabase 或 Grafana 等专业工具面板。
- **色彩策略**：单色基底 + 语义化色彩。不使用品牌主色调，颜色仅用于表达状态（如成功、错误、权限范围）。
- **排版原则**：全局左对齐（Left-align everything），通过字重和间距建立层级，而非居中对齐。

## 3. 架构与设计约定
### 3.1 字体系统 (Typography)
- **UI 字体**：`Inter`（Google Fonts）。标题使用 Semibold (600)，正文使用 Regular (400) / Medium (500)。
- **数据字体**：`JetBrains Mono`。所有 ID、Token、延迟数值及代码块均使用等宽字体，确保技术信息的可读性与可复制性。
- **字号阶梯**：页面标题 24px，正文 14px，表格头 12px（大写+字间距），微标 12px。

### 3.2 色彩体系 (Color System)
- **背景层**：
  - 基础背景：`#0a0a0f`（带蓝色调的近黑色）
  - 卡片/表面：`#12121a`
  - 悬停态：`#1a1a2a`
- **文本层**：
  - 主要文本：`#e0e0e0`
  - 次要文本：`#888888`
  - 弱化文本：`#777777`（已针对 WCAG AA 标准优化对比度）
- **语义标签**：
  - 成功/活跃：`#34a853` / `#22c55e`
  - 错误/危险：`#ff6b6b` / `#ef4444`
  - 警告：`#f5a623` / `#f59e0b`
  - 权限范围：Read (`#3b82f6`), Write (`#f59e0b`), Admin (`#ef4444`)

### 3.3 布局与组件 (Layout & Components)
- **网格系统**：左侧固定 200px 导航栏，右侧流体主内容区。
- **表格设计**：全宽无边框，表头大写且弱化，行悬停高亮。所有数据左对齐，数字不强制右对齐以保持上下文可读性。
- **徽章 (Badges)**：胶囊形状（`border-radius: 9999px`），仅用于承载语义信息。
- **交互反馈**：极简动效（150ms 过渡），无加载骨架屏（直接展示旧数据或空状态），无确认 Toast（操作结果即时可见）。

## 4. 开发者规范
1. **禁止居中**：除空状态（Empty States）和登录页图标外，严禁在表格、表单或标题中使用居中对齐。
2. **拒绝装饰**：不使用渐变背景、阴影或圆角表格。每一个像素都必须承载信息。
3. **语义化用色**：不要为了美观添加颜色。如果一个元素没有状态含义，它应该是单色的。
4. **字体匹配**：任何用户可能需要复制或属于技术标识符的内容（如 Agent ID、API Key）必须使用 `JetBrains Mono`。
5. **响应式处理**：在移动端（<768px）隐藏侧边栏，抽屉（Drawer）宽度变为 100%。
